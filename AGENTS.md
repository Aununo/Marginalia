## Project Overview

**Marginalia** is the personal website of Runzhuo Gan (also known as Aununo). It is a hand-crafted static site built with a small custom Python toolchain. There is no React, no Vite, no Jekyll, and no complex framework — just Python scripts that turn Markdown into HTML, plus hand-written HTML/CSS/JS for the rest.

The design goal is: light, quiet, interactive, and easy to edit by hand.

### Key URLs & Navigation
- `/` — Home page (typewriter hero, cursor spotlight, staggered nav cards)
- `/public/posts.html` — Blog archive with category filtering
- `/public/posts/{slug}.html` — Individual blog posts
- `/public/gallery.html` — Visual gallery (exhibition wall grid)
- `/public/projects.html` — Projects page (workbench cards + notebook)
- `/public/about.html` — About page (hand-written, polaroid layout)
- `/public/contact.html` — Contact page with floating dots background

## Build Process

### Commands

```bash
# Full build + serve on localhost:8000
./start.sh

# Or serve on a custom port
./start.sh 3000

# Build only (run the site generator without serving)
python3 scripts/build_site.py

# Build only posts (called by build_site.py)
python3 scripts/build_posts.py

# Scaffold a new post
python3 scripts/new_post.py "My Post Title" [category]
```

### How the Build Works

1. **`build_site.py`** — Orchestrator
   - Computes an asset version string: `YYYYMMDD-HHMMSS`
   - Updates cache-busting query strings (`?v=...`) in:
     - `index.html`
     - `public/about.html`
     - `public/contact.html`
     - `public/gallery.html`
     - `public/projects.html`
   - Updates the "Last updated" `<time>` element in `index.html`
   - Sets `SITE_ASSET_VERSION` environment variable
   - Calls `build_posts.py`

2. **`build_posts.py`** — Content generator
   - Reads all `*.md` files from `content/posts/`
   - Parses YAML front matter (`---` delimited)
   - Renders Markdown body to HTML using custom extensions
   - Generates:
     - `public/posts.html` — archive page with category legend and entries
     - `public/posts/{slug}.html` — individual post pages
     - `public/search-index.json` — JSON search index for the frontend
   - Cleans up stale `.html` files in `public/posts/` that no longer have a source

3. **Static pages** (`about.html`, `contact.html`, `gallery.html`, `projects.html`)
   - These are hand-written HTML. They are NOT generated by the build scripts.
   - If you change them, update them directly.

### Important Notes
- `index.html` is NEVER overwritten by the build. It is fully hand-written.
- `public/posts.html` and `public/posts/*.html` ARE overwritten on every build.
- Do not edit generated files in `public/posts/` or `public/posts.html` directly — changes will be lost on rebuild.

## Content Format

### Post Front Matter

Every post in `content/posts/*.md` starts with YAML front matter:

```yaml
---
title: Post Title
date: 2026-03-25
category: technical        # technical | reflection | article | literature | life
summary: One-sentence summary for listings.
tags:
  - tag-one
  - tag-two
preview_image: /img/posts/hello-world.svg
preview_alt: Alt text for preview image
listed: true               # false = hidden from archive but reachable by URL
format: markdown           # markdown | html
slug: post-slug            # optional; defaults to slugified filename
---
```

### Supported Markdown Extensions

The `build_posts.py` renderer enables these extensions:

- `extra` — tables, definition lists, abbreviations, footnotes, attributes
- `sane_lists` — better list nesting behavior
- `codehilite` — syntax highlighting with Pygments (`css_class: codehilite`, `guess_lang: false`)
- `toc` — table of contents (use `[TOC]` in markdown)
- Custom `GfmExtrasExtension` — GitHub-Flavored Markdown additions:
  - Task lists: `- [x] Done` and `- [ ] Todo`
  - Strikethrough: `~~deleted~~`
  - Gallery directive (see below)

### Custom Gallery Directive

For horizontally scrollable image galleries inside posts:

```markdown
:::gallery
![Alt text](/img/posts/image1.svg)
![Alt text](/img/posts/image2.svg "Optional title")
:::
```

- Use `_Prefix` in alt text to hide the caption (e.g., `![_Hidden caption](/img/...)`)
- Titles appear as meta text below the caption

### Raw HTML Posts

Set `format: html` in front matter to write the post body in raw HTML instead of Markdown.

## Code Style Guidelines

### Python
- Use `from __future__ import annotations` in every script
- Prefer `pathlib.Path` over `os.path`
- Use f-strings for formatting
- HTML is generated via large f-string templates (no Jinja)
- Keep scripts self-contained; they resolve `ROOT` from `__file__`

### HTML / CSS
- Hand-written static pages share a common nav structure. Keep it in sync across:
  - `index.html`
  - `public/about.html`
  - `public/contact.html`
  - `public/gallery.html`
  - `public/projects.html`
- CSS uses CSS custom properties (variables) extensively for theming
- Dark mode is toggled via `html[data-theme="dark"]`
- Use `clamp()` for responsive sizing
- Two stylesheets:
  - `static/style.css` — global + home + post styles (1600+ lines)
  - `static/posts.css` — archive page styles only

### JavaScript
- All site JS lives in one IIFE: `js/site.js`
- No build step for JS — write browser-compatible ES5-ish code
- Do not introduce npm packages or bundlers

## Deployment

The site is fully static. Deploy by uploading the repository root (or the relevant files) to any static host.

For local preview:
```bash
./start.sh
```

This runs `python3 -m http.server` from the repo root. The server root IS the repo root, so URLs like `/static/style.css` and `/js/site.js` resolve correctly.

---

## Security Considerations

- All generated HTML content is escaped via `html.escape` in `build_posts.py`
- External links use `target="_blank" rel="noopener noreferrer"`
- There is no server-side processing of user input; all content comes from checked-in Markdown files
- No third-party JavaScript libraries are used; all animations are CSS or vanilla JS

## Common Tasks for Agents

| Task | How to do it |
|------|--------------|
| Add a new blog post | `python3 scripts/new_post.py "Title" category` |
| Edit site nav | Update all `index.html` + `public/*.html` files manually |
| Change global styles | Edit `static/style.css` |
| Change archive styles | Edit `static/posts.css` |
| Add a new static page | Create `public/page.html` and add a link to the nav everywhere |
| Modify markdown rendering | Edit `scripts/build_posts.py` (extensions, TOC, gallery logic) |
| Update asset cache busting | Run `python3 scripts/build_site.py` — it updates `?v=` timestamps automatically |
